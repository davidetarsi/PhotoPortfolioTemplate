# M5 — Cloudflare Pages Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pubblicare il sito su Cloudflare Pages con deploy automatico su ogni push, test Vitest come gate CI obbligatorio, e chiavi API ristrette ai domini corretti (produzione + preview).

**Architecture:** Nessun nuovo file di codice. Task 1 pubblica i commit su GitHub, Task 2 crea il progetto Cloudflare Pages con build command `npm test && npm run build` e le tre variabili d'ambiente, Task 3 configura le restrizioni di dominio su GCP e Web3Forms e verifica il sito live.

**Tech Stack:** Cloudflare Pages (free tier), GitHub, Google Cloud Console, Web3Forms dashboard, Vite 8.x (`npm run build` → `dist/`).

## Global Constraints

- Build command CF Pages: `npm test && npm run build` — se i test falliscono la pipeline si blocca.
- Build output directory: `dist`.
- Node.js in CF: variabile d'ambiente `NODE_VERSION=22` (il progetto richiede ≥20).
- Variabili d'ambiente CF (Production **e** Preview): `VITE_DRIVE_API_KEY`, `VITE_WEB3FORMS_ACCESS_KEY`, `NODE_VERSION`.
- GCP HTTP referrers (tre entry): `http://localhost:5173/*`, `https://<nome>.pages.dev/*`, `https://*.<nome>.pages.dev/*`.
- Web3Forms Allowed Domains (tre entry): `localhost`, `<nome>.pages.dev`, `*.<nome>.pages.dev`.

### Task 2: Cloudflare Pages — Account + Progetto (M5.2)

**Files:** nessun file da creare — configurazione esclusivamente nel dashboard Cloudflare.

**Produce:** URL di produzione `https://<nome>.pages.dev` — necessario per Task 3.

---

- [ ] **Step 1: Crea account Cloudflare**

1. Aprire `https://cloudflare.com`
2. Cliccare **Sign Up** in alto a destra
3. Inserire email e password → cliccare **Create Account**
4. Aprire la casella email e cliccare il link di verifica ricevuto da Cloudflare
5. Completare l'onboarding saltando i passi opzionali (es. "Add a domain") — usare il link **Skip** dove disponibile

Risultato: dashboard Cloudflare accessibile.

- [ ] **Step 2: Crea il progetto Pages**

1. Nel menu laterale sinistro: **Workers & Pages**
2. Cliccare **Create** (in alto a destra) → **Pages**
3. Cliccare **Connect to Git**
4. Selezionare **GitHub** → cliccare **Connect GitHub**
5. Nella finestra popup GitHub: cliccare **Authorize Cloudflare** e selezionare il repository `your-github-user/your-portfolio`
6. Tornare nel dashboard CF: selezionare `your-github-user/your-portfolio` dalla lista
7. Cliccare **Begin setup**

- [ ] **Step 3: Configura build**

Nella schermata "Set up builds and deployments", compilare i campi esattamente come segue:

| Campo | Valore |
|-------|--------|
| Project name | `photo-portfolio` |
| Production branch | `main` |
| Framework preset | *(nessuno — lasciare None)* |
| Build command | `npm test && npm run build` |
| Build output directory | `dist` |
| Root directory | *(lasciare vuoto)* |

**Non cliccare ancora "Save and Deploy"** — prima aggiungere le variabili d'ambiente al passo successivo.

- [ ] **Step 4: Aggiungi variabili d'ambiente**

Scorrere fino alla sezione **Environment Variables (Advanced)** nella stessa schermata.

Cliccare **Add variable** tre volte e inserire:

| Variable name | Value | Environment |
|---------------|-------|-------------|
| `VITE_DRIVE_API_KEY` | *(valore del tuo `.env` locale)* | Production e Preview |
| `VITE_WEB3FORMS_ACCESS_KEY` | *(valore del tuo `.env` locale)* | Production e Preview |
| `NODE_VERSION` | `22` | Production e Preview |

Per impostare ogni variabile su entrambi gli ambienti: dopo averla inserita per Production, cliccare **Add variable** di nuovo e inserire la stessa variabile selezionando Preview dal dropdown dell'ambiente.

- [ ] **Step 5: Avvia il primo deploy**

Cliccare **Save and Deploy**.

Cloudflare eseguirà in sequenza:
1. `npm ci` — installa le dipendenze
2. `npm test` — esegue i 75 test Vitest (devono passare tutti)
3. `npm run build` — genera la cartella `dist/`
4. Upload di `dist/` sui server CF

Il processo richiede 3-5 minuti. Monitorare i log in tempo reale nella schermata del deploy.

Expected nel log: `✓ 75 tests passed` seguito da `vite build` e infine `Deploy successful`.

- [ ] **Step 6: Annota l'URL di produzione**

Al termine del deploy, l'URL di produzione appare in cima alla pagina in formato:
```
https://photo-portfolio.pages.dev
```

Se il nome `photo-portfolio` era già occupato, Cloudflare aggiunge un suffisso (es. `photo-portfolio-3x7.pages.dev`). In tal caso usare questo URL nei passi successivi.

**Annotare l'URL — serve per Task 3.**

- [ ] **Step 7: Verifica preliminare del sito**

Aprire l'URL annotato nel browser e verificare che le tre pagine si carichino:

- `https://<nome>.pages.dev/` → landing visibile (nav, hero, sezione album con card)
- `https://<nome>.pages.dev/contatti.html` → pagina contatti con form visibile
- `https://<nome>.pages.dev/album.html?album=test` → pagina album aperta (la griglia foto può essere vuota — richiede la configurazione GCP di Task 3)

Se una pagina mostra errore 500 o non si carica: aprire CF dashboard → progetto → ultimo deploy → log, cercare l'errore.

### Task 3: Restrizioni dominio + verifica live (M5.3 + M5.4)

**Files:** nessun file da creare — configurazione in Google Cloud Console e Web3Forms.

**Prerequisito:** URL di produzione da Task 2 (es. `https://photo-portfolio.pages.dev`).

In tutti i passi seguenti, sostituire `photo-portfolio` con il nome reale del progetto se diverso.

---

- [ ] **Step 1: Aggiorna i referrer HTTP della Drive API key su GCP**

1. Aprire `https://console.cloud.google.com`
2. Selezionare il progetto corretto dal menu in alto
3. Navigare in **APIs & Services → Credentials**
4. Cliccare sulla chiave API corrispondente a `VITE_DRIVE_API_KEY`
5. In **Application restrictions**, verificare che sia selezionato **HTTP referrers (web sites)**
6. In **Website restrictions**, cliccare **Add an item** e aggiungere le tre entry seguenti:

   ```
   http://localhost:5173/*
   https://photo-portfolio.pages.dev/*
   https://*.photo-portfolio.pages.dev/*
   ```

   La terza entry (con il `*` iniziale) copre tutti i preview deployments automatici di branch e PR (`https://<branch>.photo-portfolio.pages.dev`).

7. Cliccare **Save**

Le modifiche diventano attive entro 2-5 minuti.

- [ ] **Step 2: Configura gli Allowed Domains su Web3Forms**

1. Aprire `https://web3forms.com` e accedere al proprio account
2. Navigare in **Dashboard → Access Keys**
3. Cliccare sulla chiave corrispondente a `VITE_WEB3FORMS_ACCESS_KEY`
4. In **Allowed Domains**, aggiungere:

   ```
   localhost
   photo-portfolio.pages.dev
   *.photo-portfolio.pages.dev
   ```

5. Salvare

Le submission provenienti da domini non in lista vengono rifiutate da Web3Forms con errore.

- [ ] **Step 3: Verifica che le foto carichino**

Attendere 3-5 minuti dopo il salvataggio GCP per la propagazione, poi aprire:

```
https://photo-portfolio.pages.dev/album.html?album=test
```

Hard-reload per bypassare la cache: **Cmd+Shift+R** (Mac) o **Ctrl+Shift+R** (Windows/Linux).

Expected: la griglia mostra le foto dell'album Drive con l'effetto skeleton → fade-in.

Se la griglia è ancora vuota:
1. Aprire DevTools (F12) → tab **Network**
2. Ricaricare la pagina
3. Cercare request verso `googleapis.com` — se mostrano status `403`: la propagazione GCP non è ancora completata, attendere altri 2 minuti e riprovare

- [ ] **Step 4: Verifica che il form contatti funzioni**

1. Aprire `https://photo-portfolio.pages.dev/contatti.html`
2. Compilare il form: nome, email valida, messaggio
3. Cliccare **Invia**

Expected: il messaggio di feedback "Messaggio inviato. Ti risponderò presto." appare sotto il form e i campi si svuotano automaticamente (`form.reset()`).

Se appare il messaggio di errore:
- Verificare in CF dashboard (progetto → Settings → Environment Variables) che `VITE_WEB3FORMS_ACCESS_KEY` sia impostata
- Verificare che il dominio sia nella lista Allowed Domains di Web3Forms

- [ ] **Step 5: Verifica il CI gate (opzionale ma raccomandato)**

Questo step verifica che un commit con test rotti blocchi il deploy prima di raggiungere produzione. Usare un branch temporaneo per non toccare `main`.

```bash
git checkout -b test/ci-gate-verification
```

Creare un test che fallisce:

```bash
cat > src/utils/ci-gate.test.js << 'EOF'
import { expect, it } from 'vitest';
it('ci-gate — questo test deve fallire per verificare la pipeline', () => {
  expect(false).toBe(true);
});
EOF
```

```bash
git add src/utils/ci-gate.test.js
git commit -m "test: CI gate verification (branch temporaneo, da eliminare)"
git push origin test/ci-gate-verification
```

In CF dashboard → progetto → Deployments: osservare che il preview deploy per `test/ci-gate-verification` fallisce con errore durante `npm test`, senza arrivare a `vite build`.

Eliminare il branch:

```bash
git checkout main
git branch -D test/ci-gate-verification
git push origin --delete test/ci-gate-verification
```

Expected: il branch `main` rimane invariato, la produzione non è stata toccata.
